## 一、這個專題在解什麼問題

校園裡兩種算力長期錯配：

- **個體戶**（學生個人電腦）白天上班/上課、晚上睡覺，機器長時間閒置，算力浪費卻無變現管道。
- **專業戶**（實驗室、系所、簽約供應方）有 GPU 硬體與 AI 模型服務，但缺乏一個低摩擦、可信、可結算的對外租賃通道。

需求側則是大量短時、有明確終點的運算任務——影片轉檔、批次圖像處理、模型推理、程式編譯，以及學生對 AI 模型 API 的使用需求。

**我們的解法**：在 XRPL 上建一個去中心化的 **校園 AI 算力租賃共享平台**，用代幣（高科幣 / GKC）作為算力的價值載體與結算媒介，讓閒置算力變現、讓需求方以市場價格取得算力，並用區塊鏈做到非託管、可追溯、可程式化結算。

定位是 **Ripple 2026 RWA（真實世界資產代幣化）策略的校園級微型實作**：代幣不是空轉的點數，而是 1:1 綁定真實算力供給的數位憑證。

## 二、為什麼這個設計符合 RWA、而不是封閉點數

這是專題必須正面回應的第一個問題——**為什麼要用代幣、又為什麼這個代幣是「真實資產」而不是遊戲幣**。

四層產品框架的對應：

1. **價值原點**：平台創造的是真實算力（GPU 運算、AI 推理時間），不是服務承諾或封閉積分。
2. **代幣表達**：GKC 是綁定「一個標準算力單位」的數位憑證，有贖回機制——不 peg 法幣、不 peg XRP。
3. **橋接結算**：GKC 透過 XRPL 內建 DEX 與 XRP 配對，XRP 擔任燃料與兌換橋樑，平台不囤積也不發行 XRP。
4. **外部連通**：經 XRP 可橋接到 RLUSD、其他法幣或 RWA 代幣，使 GKC 有市場定價與自由退出路徑。

**明確排除**（主辦方視為不及格的設計）：封閉積分、單向兌換券、純服務承諾代幣。我們的設計刻意避開這三者。

## 三、代幣機制（高科幣 / GKC）

### 3.1 供給架構：冷 / 暖 / 熱三層錢包


| 錢包      | 角色                                                   |
| ------- | ---------------------------------------------------- |
| **冷錢包** | 寫定總量上限 **1000 億顆 GKC**。合約建置完成後銷毀私鑰 → 全球供給永遠鎖死，無人能增發。 |
| **暖錢包** | 平台主要持倉位置。冷錢包定期、固定節奏釋放至此（範例：每月 1 萬顆），直到 1000 億顆釋放完畢。  |
| **熱錢包** | 給生產環境各種自動化業務邏輯使用的錢包。                                 |


設計重點：增發無條件、固定節奏，與平台是否賣幣無關；但**增發速度應慢於業務用戶增長**，否則稀釋算力背書。

### 3.2 價值機制：錨在算力，不錨在 XRP

這是整個專題最關鍵、也最容易被質疑的一點，必須講透。

- **舊設計（已推翻）**：1 GKC = 1 XRP，平台雙向永久 1:1 兜底。問題是——GKC 價值 100% 來自 XRP，變成 XRP 的代用券（wrapper），既違背「綁真實資產、不 peg XRP」原則，又親手壓死了代幣的漲跌與稀缺空間。
- **新設計（現行）**：
  - **錨點改為「標準算力單位」**：1 GKC ≥ 可贖回一個標準算力單位。價值來自真實算力，不來自 XRP。
  - **不對稱保底**：
    - **保留地板**（賣方退出保障）— GKC 永遠可向平台贖回 ≥ 底價，滿足 RWA「可贖回」，給賣方安全網。
    - **移除天花板**（開放上漲）— 平台不再無限以 1 XRP 賣出 GKC。當真實需求 > 熱錢包釋放速度，DEX 市價自然升至地板之上，反映算力稀缺 → GKC 從 wrapper 變為具價格發現的資產。
  - **XRP 回歸本位**：結算/兌換的橋樑與燃料，不再是 GKC 的價值來源。

### 3.3 三階段撤場（冷啟動 → 成熟）

1. **早期**：平台在 DEX 提供接近 1:1 的流動性當腳手架（競賽中流動性可模擬，不需真實資金）。
2. **中期**：真實需求與賣方數量起來後，平台逐步撤出做市，僅保留贖回地板。
3. **成熟**：價格完全由 DEX 市場發現，平台只擔任「發行方 + 地板保證方」。

### 3.4 儲備自洽（早期腳手架仍成立）

冷錢包釋放到平台手上的 GKC 在賣出前未真正流通；用戶用 XRP 換 GKC 時 GKC 才流通，平台同時收進等值 XRP。故早期做市階段 XRP 儲備天然 ≈ 流通量，無額外籌資壓力；撤場後此約束自然鬆綁。

## 四、供給側矩陣


|         | 模型服務（AI，按 Token 計費） | 基礎算力（PaaS）  |
| ------- | ------------------- | ----------- |
| **專業戶** | ✅ 賣 AI（**已實作**）     | ✅ 賣硬體（尚未實作） |
| **個體戶** | ❌（無法提供模型）           | ✅ 賣硬體（尚未實作） |


- 第四格（個體戶賣模型）不成立。
- 個體戶賣硬體對應自研 OS / Bare Metal / 雙系統 / 閒置時段上線設計：平台 OS 分區由平台完全掌控，賣方自己的 Windows 分區不受干涉；個體戶本有關機習慣，重開機進平台 OS 無摩擦。

**目前開發進度：專業戶 AI 模型服務已實作；基礎算力部分尚未實作。**

### 4.1 Trust Line 准入機制（學術網路 / 實名制）

- **實作**：平台提供 QR Code → 用戶以 Xaman 掃碼 → 建立與 GKC 發行方的 Trust Line → 才能持有 GKC。
- **用途**：因持有 GKC 必須先過 Trust Line，平台可限定進場資格（如驗證學生證 → 實名制 / 學術網路准入）。
- **擴展願景**：全台學術算力共享平台。例如 5 所大學簽約供應算力，平台僅開放這 5 校學生註冊、接 Xaman、方能持有與消費 GKC。
- **定位（重要）**：Trust Line 回答了「為何不用 XRP」的**准入維度**——XRP 是全球開放資產，做不到「僅經認證者可持有並消費算力」，GKC 可以。但 Trust Line 解決「誰能持有」，不解決「值多少」；後者由第三節的算力錨定價值機制負責。兩者互補。

## 五、定價機制

### 5.1 計價基礎

賣方掛單以 GKC 計價。GKC 地板錨定「標準算力單位」，市價在地板之上由供需決定；XRP 作為換算橋樑，使「算力 → GKC → XRP → 法幣」有現實參照。

### 5.2 專業戶賣 AI

- 模型 API 普遍按 Token 計費，有明確現金價值 → 專業戶量化成 GKC 自行掛單（櫥窗/市集機制，平台不介入定價）。
- 平台只提供：① 匯率表（GKC/XRP/現金換算參考）② 基礎參考行情底盤。溢價是買賣雙方的事。

### 5.3 PaaS（基於硬體可控的腳本託管服務）

- 天然底價 = 硬體維護費 + 電費 + 賣方利潤，可參照 AWS / Azure。
- **按小時計費**：賣方自訂每小時價，買方付費使用一小時，到期關閉。
- 個體戶機器規格不一 → 不採統一秒單價，改市場機制（統一規格標示 + 評價 + 賣方自訂價，買方自選）。

## 六、消費與結算機制

### 6.1 AI 服務 → Check 機制（現行方案）

> 原本考慮 Payment Channel，但原生 Payment Channel 只支援 XRP、不支援 GKC issued asset。現改採 **Check**。

運作邏輯：

- 專業戶與平台**簽約**，故專業戶伺服器可自動把生成的 **Check** 發給平台。
- 平台將 Check 提供給消費端支付。
- 因全平台**實名制**（Trust Line 准入），欠費可輕易追查：消費端若 Check 逾期，平台可採取帳號層級動作。

這個設計把「發 Check 的責任」放在已簽約的專業戶身上，平台作中介持有並轉發，並用實名制補上信用風險缺口。Check 機制天然支援 issued asset（GKC），解決了 Payment Channel 的相容性問題。

### 6.2 PaaS → 按小時 + 到期強制截斷

- 個體戶：靠自研 OS 執行截斷（時間到切斷買方腳本）。
- 專業戶：有更強可控管裝置強制截斷。
- 付款側對接 XLS-100 Escrow（預付一小時 GKC 鎖入、服務完成釋放）為候選方向。

## 七、XLS-100 Smart Escrow

### 7.1 已推翻的舊構想

平台當中間人、爭議時人工仲裁分賬——此舉讓 XLS-100 名存實亡，退化成中心化人工託管，違背「條件自動釋放」與非託管精神。

### 7.2 現行方向

無論應用層怎麼實作，都必須真正用上 XLS-100 核心特性：**無中間人、條件式自動釋放**。平台不當中間人，回歸由買賣雙方簽署/協議決定釋放條件。

### 7.3 oracle 問題（已知，非當前主攻）

鏈上 escrow 只能依鏈上可驗證條件放款；但「服務是否真的完成」屬鏈下事件。如何把鏈下事實變成鏈上釋放條件，是已識別的硬問題。

**現階段定位**：此類細微技術不是目前主要工作。自研 OS 對個體戶硬體有實質控制權、可能充當可信見證者，留作後續設計方向。

## 九、退出路徑

賣方雙路徑退出：

1. **贖回地板**——GKC 永遠可向平台贖回 ≥ 一個標準算力單位的等值。
2. **DEX 市場**——市價在地板之上時，賣給市場可獲更高價。

平台角色：由「雙向 1:1 做市商」改為「發行方 + 地板保證方」；撤場後僅守地板、不壓天花板。
