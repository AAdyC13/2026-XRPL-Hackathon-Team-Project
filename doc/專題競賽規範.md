## 3｜XRPL 專題競賽完整規範（2/2）

### 技術方案與系統架構

- **底層協議**：XRP Ledger (XRPL)
- **錢包方案**：Xaman 非託管錢包，負責身份驗證與交易簽署
- **關鍵技術點**：
  - **信任線 Trust Lines**：建立用戶與發行方之間的授權關係
  - **資產發行 Issued Assets**：模擬 TW50 代幣的鑄造
  - **DEX 整合**：利用 XRPL 內建交易所進行資產交換

### 預期成果與成功定義

成功專案應包含以下元素：

- **實驗性**：嘗試使用 XRPL 原生借貸協議或智能託管功能
- **開發套件 SDKs**：開發能讓其他開發者輕鬆整合的功能模組
- **應用場景**：如支付 App、微型金融或各類資產代幣化

## 4｜XRPL 發幣的戰略脈絡

### 兩層概念區分

| 類型                                               | 說明                               |
| -------------------------------------------------- | ---------------------------------- |
| **XRP（原生資產）**                                | 橋接貨幣、清算層、供給有限、無超發 |
| **XRPL 上發的其他幣（Issued Assets / IOU / MPT）** | 代表現實資產的數位憑證             |

兩者互補：XRP 是清算層、其他代幣是資產層，發幣越多反而越多人用 XRP 作橋樑。

### Ripple 目前戰略（2025–2026）

已從純跨境支付鏈轉向**機構級 RWA 代幣化基礎設施**。

### 戰略證據

- XRPL 上 RWA 總值於 2026/4 突破 **30 億美元**
- RLUSD 市值破 **10 億美元**
- 已在 XRPL 發行代幣的機構：Société Générale、Ondo Finance、Archax、Deutsche Bank、Aviva

### 對本專題的意義

主辦方要求發幣精準對應 Ripple 的 RWA 戰略。  
「**發行代表現實資產的代幣 ＋ XLS-100 智能託管控制條件式流動**」正是 Ripple 2026 戰略的微縮版。

## 5｜符合主辦方期待的應用層產品框架

### 核心價值傳遞鏈

```
平台創造的現實價值 → 平台代幣 → XRP → 現實世界其他價值
```

### 四層解構

| 層次 | 名稱         | 說明                                                                                       |
| ---- | ------------ | ------------------------------------------------------------------------------------------ |
| 1    | **價值源頭** | 平台須在現實創造具體價值（電力、運算資源、時間使用權、未來收益權等），非封閉點數或服務承諾 |
| 2    | **代幣表達** | 發行代幣作為現實價值的數位憑證，與現實資產 1:1 綁定（非綁法幣或 XRP），須有贖回機制        |
| 3    | **橋接清算** | 代幣透過 XRPL 內建 DEX 與 XRP 形成交易對，XRP 作為燃料與兌換橋樑，平台不囤／不發 XRP       |
| 4    | **外部接通** | 透過 XRP 橋接至 RLUSD、其他法幣或 RWA 代幣，使代幣可被市場定價且具自由退出路徑             |

### 健全性驗證條件

- 用戶間可形成**雙向市場**（角色互換或多方需求並存）
- 代幣對「不使用者」也有持有動機（投機／儲存／轉售）
- **雙退出路徑**：DEX 交易 ＋ 發行方贖回
- 退出條件可由 **XLS-100 Smart Escrow** 程式化保障

### 排除效果

> 封閉點數、單向兌換券、純服務承諾代幣**不在主辦方期待範圍**。
